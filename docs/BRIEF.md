## 1. 这个站是什么

`Threebody.space` 是一个粉丝站。站主是《三体》小说与《我的三体》系列动画的粉丝。

**这个站要做的事**：用一个"宇宙尺度"的滚动叙事，把《三体》的世界观讲清楚，
让没读过的人看完知道这套书在讲什么，让读过的人觉得有人认真做了一次。

**这个站不要做的事**：不是产品落地页，不是 SaaS 首页，不是资源下载站，不是百科条目搬运。
所以**没有** "Get Started" 按钮、**没有** 功能卡片网格、**没有** 定价、
<!-- deslop-ignore-next-line 29 · 这里是在举反例，不是真的写了这些数字 -->
**没有** "10k+ 读者 / 99.9% 好评 / 24/7" 这类编出来的数字（taxonomy #29）。

## 2. 技术栈与工程约束

- **Vue 3**（`<script setup>` + Composition API）+ **Vite** + **TypeScript**。
- **不引入 UI 组件库**（不要 Element Plus / Naive / Vuetify）。
- **不引入 Tailwind。** 用原生 CSS + CSS 变量，写在 `src/styles/` 下。
  理由：Tailwind 的默认梯度（`gap-4`、`rounded-xl`、`indigo-500`）本身就是 slop 的温床，
  手写 CSS 反而更容易守住下面的 token 约束。
- 动画优先用 **CSS transform/opacity** 与 **Web Animations API**；
  滚动驱动用 `IntersectionObserver` + 原生 `scroll` 事件（`passive: true`，rAF 节流）。
  除非某个场景确实需要，否则**不要引入 GSAP / Three.js / Lenis**。
  如果你判断某一节（比如 §4.6 尺度尺）必须上 Canvas，用原生 Canvas 2D，别上 Three.js。
- 路由：单页长滚动为主，`vue-router` 只用于 `/`、`/sentences`（书摘全集）、
  `/works`（《我的三体》专页）、`/about`。
  首页 §4.7 放一段精选 + 入口，全部 423 条在 `/sentences`。
- 无后端。纯静态，可部署到任意静态托管。
- 内容与代码分离：所有文案、年表数据放 `src/content/*.ts`，导出带类型的常量。

### 目录建议


## 3. 视觉规范（硬约束，逐条对应 kill-ai-slop）

### 3.1 颜色 —— 一共只有五个值

```css
--void:   #000000;   /* 页面底色。全站唯一背景色，不许有第二个 */
--ink-0:  #f2f2f0;   /* 主文字 */
--ink-1:  #8a8a86;   /* 次要文字 */
--ink-2:  #4a4a48;   /* 分隔线、极弱文字 */
--signal: #c8352b;   /* 唯一强调色：红岸的那盏红灯。整页出现次数 ≤ 5 */
```

- **背景永远是纯黑 `#000`**。不许 `#0a0a12`、不许深蓝、不许 `radial-gradient` 打光、
  不许卡片自带上浅下深的表面渐变。（#06 —— 这是"高级暗色模式"最典型的 AI 味）
- **不许任何渐变文字**（`background-clip: text`）。（#02）
- **不许 indigo→violet**，不许紫，不许青橙调色。（#01）
- 强调色只有一个 `--signal`，且它有含义：**红色 = 人类发出去的信号 / 不可撤回的决定**。
  用在"1971 红岸发射"、"威慑失败"这种真正的转折点上，不要用来染标题里的关键词。（#13）
- 深浅层次靠 **`--ink-*` 三级灰**，不靠彩色。语义色一律不要（#04、#05）。

### 3.2 字体

- 中文正文：`"Noto Serif SC"` 或系统 `Songti SC / 宋体`——**这是有理由的选择**：
  《三体》是小说，中文长句用衬线读着像书，不像仪表盘。（这是对 #08 的正面回答：
  serif 用在真正的编排型内容上是对的，写清楚理由即可）
- 中文标题：`"Noto Sans SC"` 粗体，或思源黑体。标题用黑体、正文用宋体，是中文出版的常规做法。
- 拉丁文与数字：一套等宽只用在**年份、坐标、倒计时**这类真正的数据上
  （`ui-monospace, "SF Mono", monospace`），**不要用在 UI chrome 上**（#34）。
- **禁止 Inter / Space Grotesk / Manrope / Plus Jakarta Sans。**（#33）
- **禁止把某个词换成衬线斜体来"强调"**（#07）；禁止装饰性删除线、下划线、荧光笔（#09）。

### 3.3 排版层级

- 字号阶梯拉开，比例 ≥ 1.5：`14 / 17 / 22 / 40 / 88`（px，桌面）。不许所有东西挤在 14–18px（#12）。
- **display 尺寸只给能扛住它的 2–6 个字**，比如「黑暗森林」「不要回答」。
  整句营销文案不要放大到 88px（#11）。剩下的话用 17px 正文说。
- **不要 kicker。** 每个 section 上面不要顶一行 `FEATURES` 式的全大写小标签（#10）。
  分节靠尺度和留白。
- **不要 01 / 02 / 03 巨大序号**——**除非**是真有顺序的东西。
  本站的年表是真有顺序的，那里可以用年份（1971、2007、2208…），
  那是数据不是装饰。营销式的序号一律不要（#30）。

### 3.4 组件与形状

- **圆角**：全站一个值 `--r: 2px`，几乎方。嵌套时内层不圆角（#19、#21）。
- **禁止 glassmorphism / backdrop-blur 面板**（#19）。
- **禁止大面积柔和投影**。需要分隔就用 1px `--ink-2` 描边，**描边和圆角必须写在同一个盒子上**
  （#20、#22 —— 这条最容易踩：外层 `overflow:hidden` + 圆角、内层自带 border，四个角的线会被裁掉）。
- **禁止卡片网格**。这个站没有 feature card grid。内容是一条连续的叙事流。（#28、#31）
- **禁止 badge / pill 堆砌**（#23）、**禁止发光状态点**（#16）、
  **禁止圆角方块图标砖**（#18、#25）、**禁止彩色左边框 callout**（#17）。
- **禁止 emoji**（#15）。
- **不要自己画 SVG 图标**当作 logo 或插画（#24）。站点标记就用文字 `三体` 或 `Threebody.space` 排版本身。
- **间距按关系给，不要一个值刷全场**（#32）。用 `4 / 8 / 16 / 32 / 64 / 160`，
  段落内 16，段落间 64，章节间 160+。标题和它自己的正文要明显比和上一节近。

### 3.5 动效原则

这是站主明确要"炫酷"的地方，但炫酷 ≠ 到处 hover 放大。规则：

- **动效必须承载信息**。允许的：滚动推进叙事、尺度变化、数值随进度变化、元素进出场。
  禁止的：`hover:scale-105`、`transition-all`、弹簧回弹（#26）。
  hover 反馈只改 `opacity` / `border-color` / `background`，120–200ms，标准缓动。
- **载入指示器如果有，必须绕自己中心转**，`transform-origin: center`，
  居中不要写进被动画的 `transform` 里。写完看完整一圈再提交（#27）。
- **必须支持 `prefers-reduced-motion: reduce`**：关掉所有位移与视差，保留 opacity 淡入。
  写一个 `useReducedMotion()` composable 统一读取。
- 性能：只动 `transform` 和 `opacity`。滚动监听 `passive`，rAF 合并。
  首屏 LCP 图片 `fetchpriority="high"`，其余 `loading="lazy"` + `decoding="async"`。

## 4. 页面结构与逐段要求

单页长滚动，九个段落。全站底色纯黑，段与段之间靠**图片的明暗节奏**和**大留白**分隔，
不要分割线，不要 section 背景色变化。

### 4.1 开场 —— 空

- 满屏 `hero-void.jpg`（三颗星在右侧，左半边全黑）。
- 左半边黑区叠标题。标题只有四个字，88px 黑体：**三体**，下面一行 17px 灰：
  一句说清这是什么站的话（自己写，别用"不只是 X，而是 Y"句式 —— #14）。
- 唯一的动效：进入时星点 opacity 从 0 到 1，用 1.2s，错峰；标题延后 400ms 淡入并上移 12px。
- **不要滚动提示箭头的上下弹跳动画**。要提示的话，一条 1px 竖线，opacity 呼吸，或者干脆不要。

### 4.2 红岸 —— 一个决定

- 背景 `red-coast.jpg`（天线剪影 + 一盏红灯，天空全黑）。
- 内容：1971 年，红岸基地向太阳发射信号；八年后收到回复：**不要回答**。
- 唯一的 `--signal` 红用在这里：那盏红灯的位置放一个 6px 实心方点（**不要光晕、不要脉冲** —— #16），
  和「1971」这个年份。
- 「不要回答」四个字用 display 尺寸，白色，**不要红色**——红色留给"发出去"这个动作，
  不给"警告"用。这是一个可以解释的决定，写在注释里。

### 4.3 三体世界

- `trisolaris.jpg`（三日凌空，地表裂纹）。
- 讲三体问题：三颗恒星的运动无法长期预测，恒纪元与乱纪元交替，文明反复毁灭重生。
- **这里可以做一个真正炫的东西**：一个小型的三体运动可视化。
  原生 Canvas 2D，三个质点，实际跑一遍简化的引力积分（Verlet 即可），
  画 1px 白色轨迹拖尾，纯黑底。它必须**真的在算**，不是预录的路径动画。
  尺寸不要大，480×480 左右，放在文字旁边。`prefers-reduced-motion` 时画静态一帧。

### 4.4 黑暗森林

- `dark-forest.jpg`（无数极暗的竖直光针，其中一根更亮）。
- 讲两条公理与猜疑链：生存是第一需要；物质总量不变。宇宙是一座黑暗森林。
- 动效：滚动进入时，让那根更亮的针**再亮一点点**（opacity 0.6 → 1，2s），其余不动。
  一个细节动一下，比整屏动更有力。

### 4.5 水滴与降维

- `droplet.jpg`（镜面水滴）和 `two-dimensional.jpg`（太阳系被降到二维的线刻）。
- 讲末日之战与二向箔。这两张图挨着放，中间大留白。
- 水滴那张可以做一个非常克制的效果：随滚动进度，图片 `scale` 从 1.0 到 1.04，
  **只在这一处用位移**，因为"逼近"是有含义的。

### 4.6 宇宙尺度尺（站主明确要的"宇宙尺度"）

一条**可滚动/可拖动的对数尺度轴**，从人体尺度一直到可观测宇宙，把《三体》里的关键尺度钉在上面：

| 尺度 | 标注 |
|---|---|
| 1.7 m | 人 |
| 12,742 km | 地球直径 |
| 1 AU ≈ 1.496×10⁸ km | 日地距离 |
| 4.22 ly | 比邻星（三体舰队的出发地） |
| ~100,000 ly | 银河系直径 |
| ~9.3×10¹⁰ ly | 可观测宇宙 |

- 实现：一条水平（移动端竖直）的 1px 白线，刻度是 1px 短竖线，
  标签等宽字体 14px。滚动或拖动时，**数字用等宽字体连续跳变**（`font-variant-numeric: tabular-nums`，
  不许跳宽度），指数部分单独排版。
- 这是全站唯一允许"数字很大很显眼"的地方，因为这些是**真实的物理量**，不是编的 KPI（#29）。
- 这一段不要配图，纯排版。黑底白线，就是最科幻的样子。

### 4.7 书摘 —— 423 句

站内容量最大的一块，数据已备好（见 §6）。**这一节的难点不是"展示"，是"不要做成名言墙"。**

原始数据是 426 条纯字符串，清洗后 423 条，长短差距极大：
最短 5 字（「二向箔攻击」），最长 317 字（射手假说全文）。**一律同等对待是错的**，
所以清洗脚本给每条打了 `weight`：

| weight | 条数 | 字数 | 排版 |
|---|---|---|---|
| `display` | 148 | ≤ 30 | 40–88px，一屏一句，四周全是黑 |
| `normal` | 148 | 31–80 | 22px，居中一栏，最宽 34 个中文字 |
| `passage` | 127 | > 80 | 17px 宋体，正常段落，行高 1.9 |

#### 形态：一条竖直的引文流，不是网格

- **禁止砖墙 / masonry / 卡片网格。**（#28、#31）名言卡片网格是这类内容最标准的 slop 做法，
  一屏塞十二块等重的圆角框，读者一句也读不进去。
- 正确形态：**单栏、竖向、一句一屏或一句一段**，靠 `weight` 决定占多大地方。
  `display` 那 148 句每句独占一大片黑，`passage` 那 127 条按正常文章排。
  节奏由长短自然产生，不需要人为设计"变化"。
- 不要引号图标，不要 `"` 装饰大引号，不要左边框（#17）。中文引号本身就在文本里。
- 分隔：条与条之间 96px 空白，**不要分割线**。要视觉锚点的话，
  在每条左侧放一个 1px × 12px 的短竖线，`--ink-2` 色，仅此而已。

#### 一次不要全渲染

423 条全塞进 DOM 会拖垮首屏。做法：

- 首屏渲染 12 条，`IntersectionObserver` 触底再追加 12 条（不要"加载更多"按钮，
  也不要无限滚动的旋转指示器 —— #27）。
- 想做虚拟滚动也可以，但条目高度差异极大（5 字到 317 字），
  动态测高的复杂度不值得，**优先选分批追加**。
- `sentences.json` 是 156KB，**不要打进主 bundle**：用 `import()` 动态加载，
  或放 `public/` 用 `fetch`。首屏 JS 里不该出现书摘正文。

#### 对白要排成对白

52 条是多行的（`dialogue: true`），源数据里用 `\r~` 分行，清洗后是 `lines` 数组。
典型的一条：

```
孩子问，他们是烈士吗？
妈妈说，不是。
他们是敌人吗？
不是
那他们是什么？
他们是历史！
```

- 逐行渲染，行间距比段内行高略大（比如 1.9 → 2.4），**不要合并成一段**。
- 不要给不同说话人上不同颜色（#04、#13）。中文对白靠换行和「某某：」就够了。
- 不要做打字机逐字动画。这段文字的力量在内容，逐字蹦出来只会让人等。

#### 署名

28 条能可靠拆出说话人（`attribution` 字段，如「罗辑」「托马斯·维德」「章北海」）。

- 有署名的：另起一行，右对齐，14px `--ink-1`，前缀一个全角破折号。
- **没有署名的 395 条：什么都不加。** 不要写"—— 刘慈欣"，不要写"——《三体》"，
  不要标第几部第几章 —— **原始数据里没有这些信息，任何补充都是编的**（#29 的同类问题）。
  空着比猜着对。
- 多行对白里若行内自带「——某某」，那是行内署名，脚本故意没有提取
  （维德说一行、程心说一行，提到条目级会张冠李戴）。原样渲染即可。

#### 允许的动效（这一节容易动效过载，克制）

- 进入视口：`opacity` 0→1 + `translateY(8px)`→0，320ms，标准缓动。**就这一个。**
- `display` 那 148 句可以额外慢一点（560ms），因为它占满一屏，慢是合理的。
- **不要**逐条 stagger 延迟叠加（第 12 条要等 1.2 秒才出现）。
  每条独立触发，各自看到自己进视口就开始。
- **不要** hover 效果。这是文字，不是按钮（#26）。

#### 允许一个交互：随机一句

页面顶部（或 `/` 首页开场处）放一句从 423 条里随机取的 `display` 级句子，
配一个「换一句」的纯文字按钮。理由：这是粉丝站，"随手翻到一句"是真实的使用场景。

- 换句时只做 `opacity` 交叉淡入淡出，180ms。不要翻转、不要滑动、不要打字机。
- 用 `crypto.getRandomValues` 或 `Math.random` 都行，但要避免连续两次同一句。
- 这个按钮是全站唯一的交互按钮，样式：纯文字 + 1px 下边框，
  hover 只改 `border-color`。不要做成 pill（#23）。

#### 检索（可选，做了要做对）

如果加搜索框：

- 纯前端 `String.includes` 即可，423 条不需要索引库，**不要引入 fuse.js**。
- 输入防抖 200ms。**匹配结果不要给关键词上高亮色**（#13）——
  中文搜索高亮做成黄色荧光笔是典型 slop。
  <!-- deslop-ignore-next-line 13 · 这里是在规定搜索命中的正确标记方式，不是给正文关键词上色 -->
  要标记就用 `<mark>` 配 `--ink-0` 加粗、无背景色。
- 无结果时写一句正常的话，不要放插画、不要放 emoji（#15）。

## 6. 书摘数据（已备好，在 `src/content/sentences.json`）

### 来源与生成

原始数据来自站主自己的仓库，一个 426 条的纯字符串数组：
`https://raw.githubusercontent.com/AyagawaSeirin/ThreebodySpace/refs/heads/master/sentence/sentence.json`

`scripts/build-sentences.mjs` 已经把它抓下来清洗成结构化 JSON：

```bash
node scripts/build-sentences.mjs            # 联网重新抓取并重建
node scripts/build-sentences.mjs --offline  # 用 .cache/ 里的副本重建
```

清洗做了这些事，**都只是规整格式，没有增加原数据里没有的信息**：

- 按 `\r~` 拆成 `lines` 数组（106 条含此分隔符，都是对白或分行引文）
- `・` → `·`，`―――` → `——`，`...` / `···` → `……`
- 中文语境下的半角 `,` `;` `.` 转全角（英文与数字片段原样不动）
- 去掉 3 条完全重复的 → 423 条
- 单行条目末尾的「——某某」拆进 `attribution`（28 条）；
  **多行条目故意不拆**，因为每行可能各有说话人

### 数据结构

```ts
interface Sentence {
  id: string                 // 's001' … 's423'
  lines: string[]            // 一行或多行；渲染时逐行输出
  attribution: string | null // 说话人，只有 28 条有；null 就什么都不显示
  dialogue: boolean          // lines.length > 1
  chars: number              // 字符数
  weight: 'display' | 'normal' | 'passage'  // 排版分档，见 §4.7
}

interface SentenceFile {
  stats: { source, fetchedFrom, total, droppedDuplicates, withAttribution, byWeight }
  sentences: Sentence[]
}
```

实际分布：`display` 148 / `normal` 148 / `passage` 127，带署名 28，多行 52，最长 317 字。
文件 156KB —— 见 §4.7，**不要打进主 bundle**。

在 `src/content/sentences.ts` 里包一层导出类型，视图层只依赖类型，不直接读 JSON 结构。

### 内容注意事项

- 这批句子里含有大量核心剧情（黑暗森林、水滴、二向箔、程心的两次选择、云天明的童话）。
  §7 说的剧透提示同样适用于这一节。
- 少数条目在源头就是**截断的**（5 条 300 字以上的段落末尾话没说完）。
